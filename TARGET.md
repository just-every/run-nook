# Nook product direction

Nook is an independently owned daily workspace for distributed teams: familiar
conversations, explicit versioned decisions, assignee-accepted commitments and finite
attention. A proposed5–50-person cohort is a validation hypothesis, not a capacity
claim. Preserve lawful source adapters and evidence-based adoption decisions.

The authoritative implementation is the root native React/TanStack Start, Hono and
D1 Worker edition. Headless policy stays in `src/family/team-chat`. All application
source is editable and local; pinned Base runtime/onboarding and the source-authoring
tool have retained comparison origins. There is one persisted application state.

The full product direction remains public/private channels, fixed DMs, threads,
reactions/mentions/edit/delete/stable links/drafts, explicit membership/guest bounds,
invites/deactivation, owner/admin/member powers, current-ACL search/files/replay and
moderation. Channel history visibility is explicit. Decisions keep author, exact
scope, source/version history; accepted work requires its named assignee's exact
current action. Reported completion never means independent verification.

Attention remains independent of unread and work authority. Follow/mute/quiet/snooze/
done and explicit urgent requests are in-app choices. Email and Web Push are
separate opt-in channels, and Nook includes an installable PWA. Email has local
development-outbox evidence; Web Push has bounded local packet checks. Neither
proves live inbox or browser/OS delivery. The PWA service worker caches no
requests or private content, so offline operation is not supported. Saved items,
deeper needs-reply support and measured interruption outcomes remain future
acceptance. No productivity scoring, inferred responsibility or AI suppression.

Portable archives must preserve stable identities, visibility, revisions, outcomes,
media, provenance and integrity. The bounded Slack ZIP importer is shipped with
review, resumable apply, immutable read-only imported history, search and guarded
undo. It preserves source authorship, timestamps, text, metadata, threads and
supplied bytes in new private audiences; it does not create local accounts or
historical attention/work. Synthetic fixtures show bounded local behavior, not
source completeness, Slack parity or unlimited ingestion. Recovery paths are
distinct: conversion from the legacy single-workspace document is an offline
upgrade, root SQLite/native archive recovery uses the operator procedures, and
Base portability v1 requires the explicit backup-only CLI recovery with
acknowledgement of unverified metadata in `OPERATIONS.md`.

The Worker can read product content, and Nook has no third-party AI call path.
When enabled, email and Web Push call configured providers; the explicit
`node scripts/slack-files.mjs ... --fetch` operator command can fetch selected
Slack export attachments from `files.slack.com` with the supplied token. These
are deliberate external paths. Disk operators can read all data; app admins
cannot bypass DM membership. E2EE, federation and scoped AI retrieval/effects
each need explicit later threat models.
Retention must account for revisions, files, search, backups and derived data; live
logical erasure does not promise physical removal from every backup.

Pilot/adoption gates require production identity, hosted operations, invitations,
real-device notification evidence, accessibility, realistic corpus/concurrency/reconnect
measurements, signed scoped integration proof, operator upgrade/break/restore exercises
and real-team workflow outcomes. Local code/tests do not waive them. Offline use,
real-team adoption and measured interruption outcomes remain unproven. There is no
replacement or parity claim.
