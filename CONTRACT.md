# Product contract
C1 Every private API validates current active identity and current conversation membership. Search/replay/outcomes use the same policy. Workspace admins cannot read arbitrary DMs.
C2 Messages commit atomically with per-conversation event sequence and client intent key. Identical retries return the same message; changed retry payload conflicts. Replay pages preserve ordering; edits use compare-and-swap versions; deletes tombstone and erase original body from live revisions.
C3 DMs have fixed participants. Channel owners control membership. Removal revokes reads and writes immediately, including replay and search. New members currently see entire channel history; UI and docs must disclose this.
C4 A decision has a human author, conversation scope and immutable version history. Only its author revises it with version comparison. A commitment can become accepted only through the assignee's action. Completion is reported, never labelled verified.
C5 Read cursors persist per user and conversation, are monotonic and cannot exceed durable frontier. Attention/unread is separate from accepted responsibility.
C6 Restore is offline into an empty database with version and checksum verification and SQLite integrity checking. Backups contain private content and password hashes, never live sessions. No external effects on restore.
C7 Human text renders as text. No arbitrary plugin, link fetching or AI/provider effects. Bounded bodies, session expiry, password hashing, origin validation for mutations and loopback-only binding.
C8 Wider TARGET obligations remain unmet until evidence exists. No hosted, enterprise, mobile-push or unlimited reliability claim from local tests.
C9 Full backup is an offline filesystem-operator capability, not ordinary app-admin export. Operator disk access explicitly bypasses app privacy. Restore validates table identities, foreign references, schema ledger and event/read frontiers. User-readable exports are separate later work.
C10 Material commitment revision (text/assignee/deadline/scope) requires renewed assignee acceptance at the exact new version. Scope cannot move across conversations. Cancellation is explicit, terminal and versioned; authors may cancel proposals/accepted work but cannot claim assignee completion. Deleted source refs become null; event rows preserve opaque sequence/object facts, never message bodies. Replay clients fetch current object state under current ACL and interpret tombstones.
C11 Cached retry responses require current ACL before lookup. Reads synchronize monotonically across sessions; replay cursors indicate per-conversation sequence and bounded catch-up, not read receipts. History pages must cover the complete tested log rather than silently truncate.
C12 Attachments are 1 byte–25 MiB per file, five ordered files per message, with at most 50 pending/staged native uploads per uploader and no aggregate workspace byte quota. Actual bytes reside in private R2; D1 holds metadata and opaque object keys. Plain UTF-8 text, signature-checked PNG/JPEG/PDF only; forced attachment downloads plus private inline PNG/JPEG previews after structural byte validation; no inline text/PDF preview or virus-scanning claim. Staged uploads last24h for binding/read eligibility, are uploader-only under current conversation ACL, and do not create attention. Unused staged bytes remain until explicitly removed. Binding uploader-owned same-conversation IDs and message/intent/event is atomic; exact ID order belongs to retry identity. Downloads recheck current membership; delete erases live bytes/name/checksum, and message deletion cascades. The media baseline archivev2 carries actual bytes plus hashes, state and binding; current archivev3 retains these guarantees plus C13 triage and supports explicit prior-v1/v2 migration. Backups/WAL/remnants retain their stated physical-erasure limits.

C13 Calm attention is explicit per-user triage, independent of unread and outcome authority. GET/PATCH `/api/conversations/:id/preferences` accepts boolean `muted`/`followed`, requires current membership, and returns those choices plus followed root-thread IDs. POST `/api/messages/:id/follow {follow:boolean}` targets a live root thread under current ACL. Choices persist across sessions; changes affect future routing only. Muting suppresses routine follows, never explicit mentions or commitment proposals.

Message sends accept ordered unique `mentions` (at most50 current member IDs), boolean `urgent`, and `urgentReason` (1–240 characters when urgent). Urgent requests require explicit recipients. Defaults `[]`, `false`, `null` join immutable intent identity. Identical committed retries survive recipient removal without rerouting; new sends revalidate recipients. Attention creation is atomic with durable message/outcome events and stores opaque references, not copied bodies. Precedence: urgent-request, mention, thread-follow, conversation-follow. Proposals and material revisions route to assignees; assignee actions route updates to authors. Self-authored events do not create self-attention.

GET `/api/attention` returns current-ACL hydrated active items, `deferredCount`, `dndUntil`. Deleted sources hydrate tombstones, with no urgent-reason copy. GET/PATCH `/api/settings {dndUntil:epochMilliseconds|null}` controls quiet time. Quiet time defers routine items while urgent in-app requests remain visible; external delivery follows C14 email and C15 Web Push, and there is no paging guarantee. POST `/api/attention/:id {action:done|snooze,until?:epochMilliseconds}` requires item ownership and current ACL. Quiet/snooze deadlines must be future times within seven days. Snoozed items become eligible when due; routine items remain deferred during quiet time. Done changes only triage. Reading or accepting a commitment does not automatically close attention, and closing attention never accepts work.

Schema5 preserves prior ledgers and appends explicit defaults to live prior intent payloads; erased markers remain erased. Archivev3 retains follows/preferences/quiet time/triage and validates source/event/scope references. Explicit v1/v2 imports add empty attention tables and normalize prior retry identity. Old-format archives cannot carry nonempty new attention state. Root SQLite v3 and native D1 recovery formats require an explicit separately verified mapping; a source manifest alone does not establish compatibility.

C13 admission clarification: defaults apply only to omitted mentions/urgent fields, not explicit null. Explicit mentions:null or urgent:null is400 with no committed event/message/attention. Recovered dnd_until must be null or a safe integer; expired valid integers remain legal recovery values. Quiet-time domain checks precede database insertion.


C14 Email notifications reach a member away from the browser under this delivery contract. Emailable events are an explicit mention, an urgent request, a commitment proposal or material revision to its assignee, and a completion report to its author; routine thread or conversation follows, reactions, replies without a mention, accept/cancel updates and imported history are never emailed. The destination is the member's own sign-in email (an active account, verified by its sign-in link); there is no free-form address. Every member's email is off until that member turns it on in their own settings, per account: one choice covers mentions and commitments, a second covers urgent requests, with a separate choice to let urgent requests through quiet time. GET/PATCH `/api/notify {mentions,urgent,urgentQuiet:boolean}` reads and changes the caller's choices. Turning a choice off stops the next email: each queued item is checked again when its email is built. Every email carries a link that turns email off without a session (`/notify/off`: opening it shows one button and changes nothing, because mail scanners open links; the button turns all three choices off) and a link to the signed-in settings.

Queue rows are written in the same batch as the attention rows, only for recipients who turned the matching email on, and hold opaque references (recipient, conversation, actor, message or commitment, reason), never message text, file names or addresses. The ChatHub alarm drains them; pending rows keep it armed, so delivery needs no open socket and a restarted Worker resumes from D1. When an email is built, nothing is sent to an inactive member, about a conversation the member can no longer read, about a deleted or erased source, after the choice was turned off, or for an item the member already marked done or a mention they already read; each is cancelled with that reason. Quiet time (C13 `dndUntil`) holds every item until it ends; an urgent request goes through quiet time only when its recipient chose that. Each event is queued once per recipient (keyed by its attention item), so identical retries add nothing; a burst within five seconds folds into one email, and a recipient gets at most one email per conversation per ten minutes, with later items folded into a count. A failed send is retried after 15 s, 1 min, 5 min, 30 min and 2 h, then given up; a definite refusal is not retried, and a send the provider did not confirm, or that a stopped Worker may have made, is never repeated. A send being retried or given up shows as "email not delivered" with its reason class (not set up, refused, rate limited, not confirmed) to its recipient, to the member whose message caused it and to the owner for seven days, never as a silent success. Emails name the sender, the conversation (`#name`, or "a direct conversation") and a link; they never carry message text, file names, urgent reasons or commitment wording.

Mail goes through the same configured sender as sign-in (the owner deployment's provider; the development outbox under `rer dev` and `rer preview`). Accepted by the mail provider is not proof of inbox receipt, and an outbox capture is not delivery. Urgent stays an in-app request, not paging; Web Push follows C15; there is no SMS or native push. Archives carry members' choices but not the queue, so a restore sends nothing old; erasure removes a member's choices and queued items and an erased message's items.

## Native consolidation

The authoritative root native Worker uses schema4 and archivev4. Applied D1 migrations0001–0003 are unchanged;0004 adds immutable external history with no historical events, unread, attention or work acceptance. Historical root ledger1–6/archivev1–v4 and native archivev2–v3 are explicit recovery inputs; imported receipts/provenance/media remain independently recoverable. The retired Node/SQLite runtime and composition outputs are no longer application entry points. C1–C13 remain obligations, including the historical transitions described above. Historical document archives retain their original admission bounds. Normalized authority removes the whole-document size ceiling and never prunes history silently.

## Sign-in and identity

C1, C3, C9 and C11 remain current-identity/current-membership obligations. Every
private API, SSR document and workspace loader resolves a verified Base operator-auth
session and stable product ID. Owner/admin roles do not bypass conversation ACLs.
OA session expiry/revocation/operator-version fences are repeated in D1 mutation
CAS and guarded reads because auth-table changes do not advance workspace
revision. Reads do not initialize or modify the product document.

C6/C7's legacy password wording describes old recovery inputs only. New accounts
use explicit owner bootstrap and invited magic links; open registration/password
login are removed. Confirmation GET/HEAD never consumes a link; native POST
consumes once. The full Base development outbox is configured-loopback-only and
sends no external mail. Configured production auth requires HTTPS, a supported
mail provider and trusted platform client IP; it retains default Base rate limits.
Only the public sign-in presentation loader exposes the development-outbox
capability boolean, never bindings or identities. Default Base roles are owner/admin/member.

Normal archives use Base portability with semantic product validation, integrity
checking, empty-target restore and explicit credential exclusions. Legacy archive
v1-v4 conversion remains a separate recovery boundary. Prior password users have
no inferred mailbox: an explicit complete stable-ID/mailbox/role mapping and
active owner selection atomically establish auth authority in a new offline copy.
Multiple owner roles are preserved; recovery selects one explicitly active owner.
Inactive IDs, all private references and original recovery bytes are preserved.
No fresh owner automatically receives prior conversations.

## Native normalized storage (Part 3)

C1–C11 and C13 remain obligations. App reads and mutations use indexed row-level D1 storage after an explicit offline authority cutover. Every mutation batch fences the current Base operator ID, version, active status, unrevoked unexpired session and current conversation membership inside SQL. Events allocate one contiguous sequence in the same batch as the message/revision/outcome/attention/attachment changes. Internal event actors are retained where known; public replay remains opaque. Membership confers historical access, including fixed DM membership; a workspace admin receives no extra DM access.

C12 admits 1 byte–25 MiB per file, up to five ordered attachments per message, and at most 50 pending/staged native uploads per uploader. There is no product-wide aggregate media-byte quota; actual D1/R2/platform/account limits still apply. Bytes live only in the private R2 binding, never a base64 D1 cell. Binary requests are bounded by consumed bytes; legacy JSON file requests remain explicitly bounded. Filename, declared MIME, signatures and UTF-8 checks remain required, and these checks are not virus scanning. Native upload intent reserves an opaque object key durably before put, then finalizes with fresh authority. Retries after lost acknowledgements use the reservation; only finalized staged uploads bind. Staging expires after 24 hours for binding and download, and unused files require explicit removal. Deletes tombstone metadata and persist the physical-delete obligation before R2 erase. Recovery retries the erase; it never compensates an uncertain finalize by deleting a potentially bound object. Download responses force attachment disposition with no-store/nosniff. A separate PNG/JPEG preview endpoint validates the image container, rechecks current membership after reading private bytes and returns inline image bytes with private/no-store, nosniff and a sandbox CSP. The client renders a revocable blob URL in an img element. Text/PDF files remain downloads; there are no public object URLs.

History and replay seek indexed `(conversation,sequence)` frontiers. Author-aware unread counts native messages after the persisted read frontier, excluding the reader's own messages and all non-message events. Sending does not advance the read frontier. Exact case-insensitive substring search uses FTS5 trigram indexing and requires at least three characters; shorter queries return an explicit admission error. Search pages examine at most 2,000 indexed candidates and return at most 100 authorized results with an opaque continuation; a sparse page is not a declaration that no later matches exist. Attention is paged at 100 items with an explicit continuation and page-scoped deferred count. Conversation and actor directory pages currently cap at 1,000; this is a finite directory limitation, not an unlimited workspace claim.

`/api/live` carries only authorized conversation/frontier hints (and an empty-workspace refresh control), never event bodies, actor IDs or recipients. D1 replay is authoritative. Durable Object frontier comparison repairs a lost final post-commit hint, and reconnect always catches up through replay. Current session and ACL checks close revoked subscribers. The live channel delivers nothing outside the browser; C14 email is drained by the same Durable Object's alarm.

Schema migration 0010 appends normalized tables without changing 0001–0003. Existing documents stay explicitly authoritative and application traffic is paused until the offline converter validates all references, counts and R2 bytes, atomically marks normalized authority and removes the legacy document. Historical archive conversion is explicit; native legacy archive formats remain recovery inputs. Normalized backups use actual Base portability over D1 plus R2, retain stable product actors, exclude credentials/sessions/outbox/live effects, reject pending object work, and rebuild derived search after restore. Restore requires explicit identity mapping before bootstrap.

DOCS-001 Public user documentation is rendered from Markdown sources declared in `docs/site.json`. Every root and `docs/` Markdown file is published or has a reason for remaining GitHub-only; missing files, links and heading anchors fail the build. Raw HTML in a page is reported and never rendered.

ERASURE-001 Current owners/admins may erase accessible channel messages; roles never open an operator DM door. Authors retain their own delete/remove actions. Owners may erase eligible other members; admins only accounts with the member role, including guest access; self and the last active owner are refused. Every destructive commit guards current session, role and scope. Count-only preview, explicit confirmation and a subject-free receipt accompany operator erasure. Authored content, credentials and selected import copies are erased; authored work retains only scope/kind/version count/state. Other authors retain work and state without erased assignee/action attribution. Separate credential-free structural tombstones preserve threads, counters, fixed DM audiences and immutable import ownership; audit attribution and subject references are independently anonymised. D1 atomically records public Base erasure fences and durable blob obligations before R2 deletion. Completion requires verified blob absence, including resolution of uncertain puts; larger work remains pending with bounded continuation. Latest archives carry the journal and restore normally. Old archives are refused by nonempty-destination guards or the latest journal; a virgin destination without a later journal cannot recognize them. External archives, offline copies, provider backups/Time Travel and physical remnants remain outside logical erasure.

C15 Web Push is a separate opt-in channel under C14's current-identity, current-ACL, source, read/done, quiet-time, retry, visible-failure and no-paging rules. Migration 0023 preserves existing email rows and choices; all push choices start off. GET/PATCH `/api/notify` adds `push:{mentions,urgent,urgentQuiet,direct,threads:boolean}`. Mentions covers the same commitment events as email. Ordinary DMs and followed-thread replies can push without changing email or in-app Attention. Conversation-follow alone never pushes. Explicit urgent and mention reasons take precedence and require their own choice; a routine followed reply precedes ordinary DM when both are enabled. Routine follows and DMs respect mute; self-authored and imported events never push.

POST `/api/devices {transport:"webpush",subscription:{endpoint,keys:{p256dh,auth},expirationTime?:number|null}}` registers only the caller's browser subscription under the current session. GET returns only the instance VAPID public key and the caller's opaque device IDs, transport and timestamps. DELETE `/api/devices {id}` removes only an owned device. Endpoint ownership cannot transfer between accounts: unsubscribe in the browser before enabling another account. At most ten devices per person; HTTPS endpoints are restricted to the supported Apple, Google and Mozilla push hosts, keys must be valid P-256/16-byte material, redirects are refused. Relay and direct native transports explicitly reject. Each delivery rechecks the device's original session, active version, membership, preferences, native source and unread/triage state. Expired or revoked sessions and provider-expired subscriptions retire the device.

One durable queue row per event, recipient and device prevents duplicate alerts from overlapping reasons and successful-device repeats during another device's retry. Email and push have independent five-second gathering and ten-minute conversation folding windows; push windows are per device. The first due eligible item gathers the already-queued eligible burst, including items still in their initial gathering period; future retries, snoozes and quiet-held items stay deferred. A counted push uses one opaque delivery ID for the whole burst, and remains current while any folded item remains current. A conditional sending lease becomes visibly not-confirmed if interrupted, and uncertain network sends are never repeated. Failure classes show to the recipient, the sender and the owner for seven days; terminal delivery metadata lasts thirty days. Read and done transactions cancel pending push. Snoozes and quiet time defer delivery; only the separately enabled urgent-through-quiet choice overrides quiet time.

POST `/api/devices/presence {id,page,visible:boolean}` records a current-session visible-page heartbeat. Only fresh visible presence holds delivery; open sockets do not. Foreground pages renew every fifteen seconds, hidden pages release, and the alarm automatically releases expired forty-five-second presence. No browser page is needed for delivery. GET `/api/devices/sync` supplies current opaque delivered-notification IDs and badge count for foreground synchronization; the count includes unread active attention and ordinary push-enabled DM events, deduplicated across devices.

Web Push uses RFC 8291 encrypted payloads and RFC 8292 VAPID. The instance generates its key pair once on first authenticated use, storing the private key AES-GCM encrypted under a key derived from SESSION_SECRET, and sends only its public key to browsers. The encrypted payload contains sender/conversation display wording (DMs use "a direct conversation"), an authenticated same-origin app link with opaque conversation/message IDs, opaque recipient/delivery IDs, notification tag and badge count. No message body, commitment text, urgent reason or file name is included. Push services see the endpoint, timing, encrypted packet size, TTL/normal urgency, VAPID public key and signed audience/expiry/contact URI. Subscription endpoints, public encryption keys and auth material remain private D1 records. Archives exclude keys, devices, presence and all delivery state; restored installations send nothing old. Member/message/outcome erasure removes associated push records. Logical erasure cannot retract packets already accepted by a push service or notices already displayed on a sleeping device.

The installable PWA preserves Nook's UI and authenticates navigation on every notification tap. Its service worker caches no requests or private content. Permission requests require a gesture; the foreground reconciles allowed subscriptions and visibly reports re-enable failures. The previous open-tab OS notification path is removed; the title count remains. Every Web Push shows a visible notification and can update its badge. No badge-only or clear-only background Web Push is sent: WebKit revokes silent subscriptions. Foreground authoritative refresh closes read/revoked notices and updates badges through the service worker. Immediate clearing on a sleeping device, native iOS badge updates and Android native normal-priority clears remain blocked until a native transport exists. Browser acceptance is not proof of OS receipt; C8's evidence limits still apply.
